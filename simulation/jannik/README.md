# Simulation – Jannik's implementation

Motion logic for the RPM, the Arduino Nano firmware that runs it, and a simulation that checks it
against measurable acceptance criteria. Author: Jannik Greiner (simulation team).

This is one of two independent implementations in `simulation/`, so the testing team can test and
compare both; the other one lives directly in `simulation/` (`rpmcore` + MuJoCo). Both use the
team conventions from [`docs/interfaces.md`](../../docs/interfaces.md): axes `outer`/`inner`,
speeds in deg/s, pulses in µs. The controller is an **Arduino Nano** (ATmega328P, also CH340
clones), see [ADR 0003](docs/adr/0003-arduino-nano-firmware.md); the earlier Pico firmware is kept
in `firmware/` until the team has agreed on the new wiring in `docs/interfaces.md`.

**Result:** the default `clinostat` strategy brings the time-averaged gravity on the sample below
**0.003 g** after 10 minutes in every simulated run, even with ±20 % servo error. Plots in
[`results/`](results/README.md), reasoning in [`docs/adr/`](docs/adr/), API and criteria for tests
in [`docs/api.md`](docs/api.md).

## Layout

| Path | What | Runs on |
|---|---|---|
| `rpm/core/` | reference motion logic (Python), tested by the simulation | PC (and Pico) |
| `rpm/sim/` | simulation of the real servos, report, `rpm-sim` CLI | PC |
| `firmware/nano/rpm_nano/` | Arduino sketch: C++ port of `rpm/core`, serial commands, `config.h` | **Nano** |
| `rpm/nano/` | `rpm-nano-calibrate`: measures the servo curves over USB | PC |
| `firmware/*.py` | earlier MicroPython firmware (legacy, see above) | Pico |
| `tests/` | pytest suite; `tests/nano/` C++ tests of the sketch; `micropython_smoke.py` | PC |
| `results/` | latest strategy comparison (generated by `rpm-sim compare`) | – |
| `viewer/` | 3D browser viewer, plain HTML + JS; runs go to `viewer/data/` (generated) | browser |
| `docs/` | API and acceptance criteria, decisions (ADRs) | – |

The Nano cannot run Python, so the sketch is a line-by-line C++ port of `rpm/core`. CI compiles it
on the PC with 32-bit floats and checks that it moves the machine exactly like the Python code the
simulation tests: the same timer events, the same pulses (up to float rounding) and the same
estimate over a simulated hour. It also checks that the sketch fits the ATmega328P.

## Simulate on a PC

Needs [uv](https://docs.astral.sh/uv/) (it fetches Python 3.11+ and all packages).

```bash
cd simulation/jannik
uv sync
uv run rpm-sim run clinostat                  # one 10-minute run, prints the metrics
uv run rpm-sim run random_walk --speed-error 0.2 --noise 0.03
uv run rpm-sim compare                        # all strategies -> results/README.md + plots
```

## Watch it

```bash
cd simulation/jannik
uv run rpm-sim viewer                         # exports the 3 strategies once, opens the browser
uv run rpm-sim export random_walk --minutes 5 --speed-error 0.2   # another run for the viewer
```

`rpm-sim viewer` serves the repo root on <http://127.0.0.1:8000/simulation/jannik/viewer/>
(`--port` to change it) because the viewer loads the printed parts straight from
`rpm_printables/`. It replays a run on the real parts and shows, next to the machine, the gravity
direction seen by the sample (dot, trail, every direction visited), the running mean against the
target, and the residual gravity over time with the 0.01 g limit. Space plays and pauses, the arrow
keys step, clicking the chart seeks.

Each export lands in `viewer/data/` (git-ignored) and appears in the viewer's dropdown. The JSON
format is documented in [`rpm/sim/export.py`](rpm/sim/export.py). The viewer needs internet access
once for three.js (pinned 0.160.0 from jsDelivr). The gears' positions along their axes are
approximate, the STLs do not fix them ([PLAN.md 2.3](../../docs/PLAN.md)).

## Checks

```bash
cd simulation/jannik && uv sync
uv run pytest                    # unit tests + acceptance criteria in simulation (~4 s)
uv run ruff check . && uv run ruff format --check .
uv run mypy
MICROPYPATH=.:firmware:tests/fake_pico micropython tests/micropython_smoke.py   # legacy Pico
```

`uv run pytest` includes the Nano tests: they need a C++ compiler (`c++`), and the size check needs
[arduino-cli](https://arduino.github.io/arduino-cli/) with `arduino-cli core install arduino:avr`
and `arduino-cli lib install Servo`; without them those tests are skipped.

CI runs all of them on every PR that touches `simulation/jannik/`
([workflow](../../.github/workflows/simulation-jannik.yml)).

## Run on the machine (Arduino Nano)

**Wiring** (proposed for `docs/interfaces.md`): outer servo signal → **D9**, inner servo signal
(through the slip ring) → **D10**. Power the servos from a separate **5 V supply of at least 2 A**
(two stalled FS90R draw up to 1.6 A); connect its GND to the Nano's GND. Do not power the servos
from the Nano's 5V pin: USB and the Nano's regulator cannot deliver that current.

**Flash** with the Arduino IDE (board "Arduino Nano", processor **"ATmega328P (Old Bootloader)"**
for most CH340 clones; if uploading fails, try "ATmega328P"; install the CH340 driver if no port
appears) by opening `firmware/nano/rpm_nano/rpm_nano.ino`, or from the command line:

```bash
cd simulation/jannik/firmware/nano
arduino-cli core install arduino:avr && arduino-cli lib install Servo
arduino-cli compile --fqbn arduino:avr:nano:cpu=atmega328old rpm_nano
arduino-cli upload  --fqbn arduino:avr:nano:cpu=atmega328old -p /dev/cu.usbserial-110 rpm_nano
```

After power-up it starts the clinostat on its own (`AUTOSTART` in `config.h`); the onboard LED
blinks while it runs. Over USB serial (115200 baud, line ending "Newline", e.g. the IDE's serial
monitor or `arduino-cli monitor -p <port> -c baudrate=115200`) it takes the commands of
[`docs/api.md`](docs/api.md#serial-commands-nano): `status`, `start random`, `stop`, `estop`,
`pulse outer 1600`, …

**Calibrate** once per machine (recommended): with the machine assembled, run

```bash
uv run --group nano rpm-nano-calibrate --port /dev/cu.usbserial-110
```

and time one revolution of the driven axis per pulse width with a stopwatch. It writes
`firmware/nano/rpm_nano/calibration.h` (only if the curve is valid); flash again to use it.

### Earlier: Raspberry Pi Pico (MicroPython)

The MicroPython firmware in `firmware/` still works on a Pico (GP15/GP16): copy `rpm/core/` and
`firmware/*.py` with `mpremote`, then `import calibrate` in the REPL to calibrate. It will be removed
once the team has agreed on the Nano.

## Strategies

| Name | Motion | Use |
|---|---|---|
| `clinostat` | outer 120 deg/s, inner 0.382 × that, constant | default |
| `random_walk` | random speed and direction per axis, ramped | comparison |
| `random_setpoints` | original Core Electronics behaviour | baseline |

Why the clinostat wins and why coverage is not uniform:
[ADR 0002](docs/adr/0002-clinostat-default-strategy.md).
